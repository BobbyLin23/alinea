# Working in alinea

This is a Bun/TypeScript monorepo created with Better-T-Stack. The current app is a starter page with an API health check; auth, database integration, and product workflows are not implemented yet.

## Package boundaries

- `apps/web`: React SPA built with Vite and TanStack Router. Put routes in `src/routes` and app-specific components in `src/components`.
- `apps/server`: Hono HTTP server. Owns middleware, CORS, environment loading, and request context creation; mounts the shared tRPC router at `/trpc`.
- `packages/api`: Shared tRPC procedures, routers, and context contract. Implement API logic here and assemble routers in `src/routers/index.ts`.
- `packages/ui`: Shared shadcn/Base UI components, utilities, and design tokens.
- `packages/config`: Shared TypeScript configuration. Check each workspace's `tsconfig.json` before assuming it inherits the base config; the web app has its own configuration.

Keep framework-specific request handling and environment access in the owning app. Extend `packages/api/src/context.ts` and `apps/server/src/context.ts` together when adding request-scoped dependencies. Shared packages should receive configuration or initialized clients from the app rather than importing app modules.

## Development and validation

Use Bun and the committed `bun.lock`. Read the root and affected workspace `package.json` scripts before choosing commands. Shared dependency versions live in the root workspace catalog; use `catalog:` for dependencies already managed there and `workspace:*` for internal packages.

- Install with `bun install --frozen-lockfile` when dependency changes are not needed. Installation also generates env types.
- Local development uses web port `3001` and API port `3000`. Set `VITE_SERVER_URL=http://localhost:3000` in `apps/web/.env.local` and `CORS_ORIGIN=http://localhost:3001` in `apps/server/.env.local` if local values are missing; preserve existing values.
- `bun run check` runs Biome **with `--write`** across the repo. For scoped code changes, use `bunx biome check --write <changed-files>` and review the resulting diff. Formatting and lint rules are defined in `biome.json`.
- Run `bun run check-types` for code changes. The web workspace's check also runs a Vite build, which generates the route tree and loads/validates its environment. Missing env values can fail this check before TypeScript runs.
- Run `bun run build` when changing bundling, dependencies, or deployment behavior. Server builds bundle `@alinea/*` packages but leave runtime dependencies external; deployments need the app's `.env.schema` and Varlock dependencies available.

There is currently no test script or test suite. Validate changed behavior with a focused runtime/browser check as appropriate, and report checks actually run and any blockers. Documentation-only changes need a diff and whitespace check, not an application build.

## Frontend and shared UI

Add file-based routes through `apps/web/src/routes`; `src/routeTree.gen.ts` is generated by the router plugin and ignored by Git. Regenerate it through Vite rather than editing it.

Use the existing tRPC options proxy and QueryClient from `apps/web/src/utils/trpc.ts` for server state, following `useQuery(trpc.healthCheck.queryOptions())`. Import `AppRouter` as a type so frontend code does not pull in server implementation.

Import shared primitives through `@alinea/ui/components/<name>` and `cn` through `@alinea/ui/lib/utils`. The `@/` alias refers to the owning app's `src` directory. Shared packages expose source files directly; they do not need a separate build before app development.

The UI uses shadcn's `base-lyra` style and Base UI. Follow existing primitive APIs, including `render` composition as shown in `apps/web/src/components/mode-toggle.tsx`; Radix `asChild` examples do not match these components. Add shared primitives to `packages/ui` and keep app-specific compositions in `apps/web`.

Global styles and light/dark tokens live in `packages/ui/src/styles/globals.css`, imported by `apps/web/src/index.css`. Use semantic Tailwind colors and existing component variants so changes work in both themes. Preserve the CSS source declarations that scan both apps and the shared UI package.

## Environment and generated files

Each app's `.env.schema` is the source of truth for environment variables. After schema changes, run `bun run env:generate`; generated `apps/*/src/env.ts` files are ignored and should be regenerated rather than edited or committed.

Use the generated `ENV` accessor. Server code imports it through `apps/server/src/env.server.ts`, which loads `varlock/auto-load`; the web app loads Varlock through its Vite integration. Bun's automatic dotenv loading is intentionally disabled in root and app `bunfig.toml` files.

Keep secrets in ignored env files or deployment configuration. Expose browser variables explicitly with `@public` in the web schema. Run standalone tools that load Varlock from the owning app directory; code generation alone does not initialize env values for a later command.
